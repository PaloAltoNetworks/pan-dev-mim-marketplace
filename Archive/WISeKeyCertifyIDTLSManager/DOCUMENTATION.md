# WISeKey CertifyID TLS Manager

## Getting started

To use WISeKey CertifyID TLS Manager Venafi Adaptable Framework CA, following fields must be filled:

| Field Name       | Description                                                            | Value                                                                            |
| ---------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `ServiceAddress` | TLS Manager API Host                                        | `https://tlsmanager.certifyid.com/api`                                           |
| `Username`       | API Application ID                     | [Obtain Application ID](#steps-to-obtain-application-id-and-secret-key) |
| `Password`       | API Application Secret Key                         | [Obtain Secret Key](#steps-to-obtain-application-id-and-secret-key)     |
| `CSR`            | Certificate signing request | [CSR description](#csr)                                                        |
| `Custom Fields`  | Additional parameters to create requests                                  | [Custom Fields Configuration](#custom-fields)                                    |

## Obtain Application ID and Secret Key

 AppID and AppKey are provided by WISeKey TLS Team for use in authenticating with the TLS API.

## CSR

To issue certificates as public SSL for one or some domains, these domains must be included in the SAN of the CSR.

- CSR must be in PEM format and accepts containing header and footer.
- Only supported CSR in PEM format of RSA-2048, RSA-4096, ECDSA P-256, ECDSA P-384.
- If the CSR has the CommonName, then the value must be a DNS Name.
- Certificate's SAN is coming from the SAN of the CSR.
- Certificate's SubjectDN is not coming from the CSR but will be auto-generated by TLS system.
- Common Name will be taken from the first DNS in CSR's SAN.

Setting-up of the custom fields:

| Field No. | Field Name                  | Description                                                                                                                 | Type                | (\*required) |                                                                                   |
| --------- | --------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------- | ------------ | --------------------------------------------------------------------------------- |
| 1         | `ProductID`                 | ID of the WISeKey TLS Product                                                                                               | number              | true         | [Obtain Product ID](#steps-to-obtain-product-id)                                  |
| 2         | `SubscriberID`              | ID of WISeKey TLS Subscriber                                                                                                | number              | true         | [Obtain Subscriber ID](#steps-to-obtain-subscriber-id-and-subscribers-contact-id) |

| 4         | `CertificateValidityPeriod` | Validity period of certificate in days                                                                                      | number (minimum: 1) | false        |
| 5         | `DomainValidations`         | Setting-up validations for each DNS Name in certificate's SAN. If DNS Names are pre-validated, then this should be ignored. <br/>- Format: `[DNS_Name]:[Validation_Method];[DNS_Name]:[Validation_Method];...`<br/>- Example: `domain1.com:txt_http_file;domain2.com:txt_dns_record;domain3.com:whois_email:myemailaddress@mydomain.com`<br/>- WISeKey TLS currently supports the following validation methods:<br/><ul><li>`txt_dns_record`: DNS TXT Record</li><li>`txt_http_file`: Http File Auth</li><li>`constructed_email`: Constructed Email</li><li>`txt_dns_email`: DNS TXT email contact</li><li>`whois_email`: DNS WHOIS-based Email</li><li>`dns_cname`: DNS CNAME Record</li></ul> | string              | false        |

## Steps to obtain `Product ID`

   Login to TLS Manager web portal with your Partner account:
   [WISeKey TLS Manager](https://tlsmanager.certifyid.com/)

   Navigate to the product table from the main menu.   
   `Products` > `Products`

   Find the ID of the product.

## Steps to obtain `Subscriber ID` and `Contact ID`

Login to TLS Manager web portal with your Partner account:
   [WISeKey TLS Manager](https://tlsmanager.certifyid.com/)

   Navigate to the subscriber table from the main menu.   
   `Subscribers` > `Subscribers`

Find the ID of the subscriber.

Navigate to the subscriber details page.

Find the ID of your contact in the contact table.
